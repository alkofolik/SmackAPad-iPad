# 216 — From memory: peek at the pattern (manual and automatic)

Status: open. Decided by Jakub on 2026-11-22 after he kept forgetting the pattern in From memory and had to stop the lesson. Mockup: design canvas "Smack-a-Pad – návrhy (kolo 22. 11.)", artboard D (approved: "může být"); the artboards are only a guide for look and behaviour.

## Goal

In From memory, when the notes are hidden, the player can show them again for the rest of the current pass without stopping the lesson. The same happens automatically after repeated failures. A pass during which the notes were shown never counts.

## Decisions (Jakub, 2026-11-22)

1. **Manual peek:** tapping the orange band, or a small eye button above the band at the right, or a controller button the player assigns, shows the notes until the end of the current pass. The lesson keeps running.
2. **Automatic peek:** after **two hidden passes in a row** with a score below the pass mark, the next pass starts with the notes shown. On by default, switchable off in Settings (section "Practice screen", next to "Fade notes in From memory").
3. **A peeked pass never counts.** It is treated like the existing warm-up pass with visible notes: no review step, no memory star, no from-memory credit. Passes before and after it keep their results; nothing already earned is removed.
4. Peek exists only in From memory, only while notes are hidden (`noteVisibility == .hidden`), not in Listen, not in After me, not in a section loop.
5. No new text on the practice screen except one short reason in the result card (see rule 8). Use the eye symbol only.

## Rules

1. **State.** Add a peek flag to `PracticeSession` for "the current pass was peeked" (set on trigger, cleared when the next pass starts). Do not put anything that changes per frame or per hit into observed state; see ticket 209. The eye button and the remaining-time line are leaf views.
2. **Visibility.** `NoteVisibility.derive` (`PatternField.swift`) gets a peek input. With peek active the notes are drawn as `.shown`. Fade in about 0.15 s, fade out at the pass boundary about 0.25 s; with Reduce Motion no fades. Do not touch the ticket 215 fix for run boundaries.
3. **Not counted.** In `PracticeSession` the pass evaluation already uses `memoryNotesHidden` / `isHiddenPass` (~line 1183). A peeked pass must take the "notes visible" path there, including `reviewPendingReason`. Add a reason `peeked` next to `.notesVisible`. `memoryWarmUp.recordPass` must not be advanced by a peeked pass.
4. **Automatic peek counter.** Count consecutive hidden, non-peeked passes with score below `LearningRules.passMark`. Reset it on any pass at or above the mark, on STOP, on leaving the lesson. At two, flag the next pass as auto-peeked and reset the counter. Put the counting rule in `LearningRules.swift` so it can be unit tested.
5. **Tap on the band.** A single tap on the band triggers peek only when the conditions in decision 4 hold; otherwise it does nothing. It must not interfere with pad input, with the long-press hints, or with the touch pads in portrait.
6. **Eye button.** 36×30 pt, top right above the band, drawn only in From memory. Outline when idle, filled orange while peeking, a soft glow once when automatic peek starts. Spacing: follow the app-wide rule that buttons never touch; do not squeeze the HUD items at the top right (requirements, rushing/dragging readout). If there is no room, put the eye at the far end of the HUD row and tell Jakub in the ticket.
7. **Remaining-time line.** While peeking, a 3 pt line above the band shows how much of the pass is left. Use the display-clock approach from ticket 208; no per-frame work in `PracticeScreen.body`.
8. **Result card.** For a peeked pass the card shows the existing "Not counted" state with one short reason string, English "Peeked · only passes from memory count." (Czech translation too). No stars change.
9. **Controller button.** Add a learn target `peek` next to the existing controller mapping rows (`ControllerSetupView.swift`, `MIDIControlLearnTarget`, `MIDIControlRouter`). Default: unassigned. The button works only on the practice screen.
10. **Settings.** New `autoPeekMemory` in `SettingsManager`, default **true**, a toggle "Automatic peek in From memory" with a one-line footer "After two missed passes the notes show for one pass. That pass does not count." Persisted and included in the settings backup (`ProgressBackup.swift`, old backups without the field import as true).
11. **Help.** Update the From-memory help card (and tutorial card if it mentions From memory) with one short sentence about peek, Czech and English. Do this only after the audit in ticket 214 is done, so the two do not fight over the same strings.
12. Do not change scoring thresholds, the two-good-passes rule for hiding notes, review scheduling or the ticket 209 per-hit observation rule.
