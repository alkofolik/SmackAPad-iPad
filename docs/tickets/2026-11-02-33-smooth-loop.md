# 33 — Smooth scrolling across run repeats

Status: implemented; tape regression passed; existing text-test failures and iPad verification remain. Source: Jakub's test 2026-11-02 (feedback round 5). Highest priority: it breaks his rhythm.

## Problem

In auto-repeat the scrolling pattern hitches at the boundary between runs. The colours of played pads on the pattern also behave badly when a new run starts: both the ones arriving and the last few from the previous run that are still visible.

## Goal

Pattern scroll is visually continuous across run boundaries. No jump, stall, speed change or restart of an animation. Played-pad colours stay in the same continuous coordinate system, so nothing jumps or disappears at the boundary.

## Rules

- Derive the pattern position from **one continuous clock** (the audio engine time already used for scheduling), never from a per-run counter or a per-run animation that is recreated.
- Model the scrolling view as an endless tape: the end of a run joins the start of the next without a gap. Draw enough of the next run ahead of the marker.
- Played-pad colours (right / wrong) are stored with the tape position they belong to. They fade only when they scroll out of view, never when a run resets. Keep the "last few hits stay coloured" behaviour agreed in round 3.
- Do not change scoring, star rules, tempo-up or the count-in.
- Static view is unaffected, but its "clear on next pass" behaviour stays.

## Implementation — 2026-11-02

The old display wrapped its local position using the scheduled audio pass, but read the pass number and tempo from the separate 10 ms session tick. At a boundary these described different repeats, briefly attaching feedback to the wrong notes. Scrolling also reused the static view's pass-tail expiry, removing colours while notes were still visible.

- Added a single host-clock display sample with absolute tape position, local position, repeat identity and scheduled tempo. Drawing does not clamp or reset at repeat boundaries.
- Scrolling notes and played strikes use absolute tape coordinates. Feedback is read by the note's own repeat and fades only at the viewport edge. Static feedback behaviour and all user-facing strings are preserved.
- Added a session regression covering ten boundaries for each combination of 60/90/140 BPM and 1/2/4 bars. It samples across a boundary before the scheduler tick and again after it, and checks judgment/played-strike retention.
- The original calculation reproduced a backward delta of approximately 16/32/64 steps at the boundary; the regression failed as expected before the fix.
- Device acceptance remains with Jakub: scrolling, 90 BPM, 2 bars, 10 repeats, including played-note colours.
