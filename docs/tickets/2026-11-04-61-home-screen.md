# 61 — Home screen (implementation of proposal A, changed to a 3×3 pad grid with the logo in the centre)

Status: ready. Source: Jakub, 2026-11-04, choosing from ticket 60 (`docs/design/2026-11-03-home-screen/`). Ticket 60 is done.

## Decisions by Jakub

1. **Proposal A, "the logo is the menu", but as a 3×3 grid** (not the four large pads of the HTML). **The centre cell is the logo mark: inert, no frame, no background.** The other eight cells are pads.
2. **Eight actions**, listed below. Progress is not a pad; the star count moves to the Library pad.
3. **Colours follow the rest of the app** (`Theme` tokens, light and dark). The cream-in-both-appearances recommendation of ticket 60 is **not** adopted for the home screen. Only the animation itself still starts on cream (the static launch screen of ticket 46 stays unchanged).
4. **Navigation**: Home → Library → Practice. Back from the library goes to Home; back from a lesson goes to the Library (as today).

## Known defect in the proposal: ignore its wordmark

In `proposal-a.html` the wordmark is clipped. Its SVG has `viewBox="0 0 490.455 73.8"` while its path coordinates live in the original logo's coordinate space (starting at about x 110, y 60), so only a corner of it is visible. **Do not copy any SVG from the HTML.** Use the wordmark that already exists in the app (`LaunchWordmark.imageset`, preserves vector data) and the logo geometry from `LaunchAnimationView.swift`. The finished logo with wordmark must be **complete, uncropped and centred in its area** in portrait and landscape on 11" and 13", in light and dark (see acceptance criteria).

## Layout

One 3×3 grid, centred; the wordmark "Smack-a-Pad" sits **above** the grid (portrait and landscape), large and centred. The logo mark (three black pads + rotated orange pad, as in `LaunchAnimationView`) fills the centre cell.

```
              Smack-a-Pad
┌────────────┬────────────┬────────────┐
│ POKRAČOVAT │  KNIHOVNA  │  NASTAVENÍ │
│  (orange)  │  42/216 ★  │            │
├────────────┼────────────┼────────────┤
│  ÚVODNÍ    │  logo mark │  OVLADAČ   │
│  CVIČENÍ   │ (no frame) │            │
├────────────┼────────────┼────────────┤
│ KALIBRACE  │ PLNÁ VERZE │ O APLIKACI │
└────────────┴────────────┴────────────┘
```

- Portrait (834×1194): wordmark on top, grid below using the full width. Landscape (1194×834, 13"): the grid is limited by the height and centred horizontally; the wordmark above it. Empty space left and right is acceptable.
- Cells are squares sized from the available area (gap `Theme.Space.regular`, outer margin `Theme.Space.wide`), computed from the container size (`GeometryReader`), so it also works in Split View / Slide Over; no hard-coded device sizes.
- Labels in IBM Plex via existing `Theme` fonts (`Theme.action` for the label, `Theme.meta` for the second line); long labels may use two lines and `minimumScaleFactor` down to 0.8, never truncate with "…". Pad corner radius `Theme.Radius.pad`.
- Pressed state: darker fill and a 0.97 scale for 0.1 s (a tactile pad); no sound, no glow.

## Animation → home

Rework `LaunchAnimationView` so its last frame **is** the home screen (today it fades out). Keep the existing logo build (pads pop, orange smack at 12°, wordmark rise); the timeline becomes:

| Time | What happens |
|---|---|
| 0.00–1.50 s | As today on cream, but the logo is built **at the centre of the screen**: three black pads, the orange smack, then the wordmark. |
| 1.50–2.10 s | The logo mark scales down to the centre cell of the grid and the wordmark moves above the grid. At the same time the background cross-fades from cream to `Theme.background`, and in dark appearance the logo cross-fades to its on-dark colours (`docs/design/2026-11-03-logo-source/smack-a-pad-logo-horizontal-on-dark.svg`; give the asset catalog image set a dark variant). |
| 2.10–2.80 s | The eight pads appear **outward from the centre**: first the four edge-adjacent pads (2, 4, 5, 7) together, then the four corner pads (1, 3, 6, 8) 0.12 s later, with a small scale/opacity pop. Each pad is tappable as soon as it is visible. |
| 2.80–3.20 s | Done. The animation never fades the logo out. |

- Tap anywhere during the animation jumps to the finished home screen.
- Cold start only. Returning from background does not replay it. Returning Home from the Library or a lesson shows the finished home screen with at most a 0.25 s cross-fade (no logo animation).
- **Reduce Motion**: no movement; the finished home screen fades in over 0.25 s.
- The animation must not delay `store.start()` / `midi.start()` / data loading (as in ticket 46).
- Remove the `preferredColorScheme(.light)` workaround in `SmackAPadApp.swift` only if it is no longer needed; the animation's cream stage must still look right in dark appearance.
- Native SwiftUI only; no new packages.

## Navigation

- `SmackAPadApp` root shows the Home screen and the Library as two routes with a simple transition (0.25 s cross-fade; `Theme.Motion` policy for Reduce Motion). Settings, calibration, purchases and About are sheets/popovers from Home as in the table.
- `LibraryScreen` gets a small launch parameter (nothing / Intro page / present this lesson) set by pads 1 and 4, and a **"Domů / Home" button** that returns to Home. It must be reachable in one tap, at least 48 pt high, and must not collide with the sidebar toggle or the existing Settings button; choose the placement (sidebar toolbar leading is the recommendation) and mention it in the report.
- A lesson opened through Continue returns to the Library when closed (the existing behaviour of the practice screen). The Library's own "Next" banner stays as it is.
- No change to the practice screen, scoring, audio, MIDI or the existing settings content.
